# ロードマップ — 接骨院・整体向け AI 統合運営パッケージ

## フェーズ概要

| フェーズ | 期間目安 | ゴール | 対象院 |
|---|---|---|---|
| **Phase 0 — 検証** | 〜1 ヶ月 | 要件・UX 検証、紙プロトで院長ヒアリング | 既存口コミツール顧客 3 院 |
| **Phase 1 — MVP** | 2 〜 3 ヶ月 | P0 機能で 1 院の 1 日を回せる | PoC 2 〜 3 院 |
| **Phase 2 — β** | 3 〜 4 ヶ月 | P1 機能追加、AI エージェント本格化 | 有料 β 10 〜 20 院 |
| **Phase 3 — GA** | 6 ヶ月〜 | マーケ開始、100 院達成 | 全国 |

---

## Phase 0 — 検証（紙 + Figma）

**目的**: コード書く前に「院長が本当に払うか」と「一人オペの本当のボトルネック」を確定する。

- [ ] 既存口コミツール顧客 3 院にヒアリング（1 日の業務シャドウイング含む）
- [ ] 競合調査（ジェナス・グリーンカルテ・メディカルフォース等）
- [ ] 問診 UI と部位選択 UI の Figma プロト
- [ ] 価格感の当て（¥29,800 で通るか、オーダーメイド要望の有無）
- [ ] PoC 契約書・個人情報取扱同意書のドラフト

**Exit 条件**: 3 院中 2 院以上が「MVP 完成時に有料 PoC 参加」を口頭合意。

---

## Phase 1 — MVP（P0 機能のみ）

**目的**: 1 院のオーナーが**朝から閉院まで本当に一人で回せる**最小構成。

### 実装順

1. **基盤**（1 週目）
   - モノレポ初期化、Prisma schema、認証、RLS
   - Clinic / Patient / Visit の CRUD と管理画面
2. **予約 + LINE**（2 週目）
   - Web 予約 + LINE Bot Webhook
   - 院長カレンダー（日/週）
3. **AI 問診**（3 〜 5 週目）★ 本体
   - 人体図 UI、基本情報フォーム
   - Claude Sonnet 4.6 の対話ループ、Tool use 一式
   - 赤旗検出ルール
   - Opus 4.7 のサマリ生成 → カルテ下書き
4. **カルテ**（6 週目）
   - 施術記録 UI、音声入力 → 整形
   - 時系列ビュー
5. **会計 + レシート**（7 週目）
   - Stripe 連携、PDF 発行
6. **口コミ + 再来**（8 週目）
   - 既存ツール統合、会計後トリガー
   - 離脱患者リスト + LINE DM
7. **ダッシュボード + AI 週次レポート**（9 週目）
   - 売上/来院/新患、Opus 4.7 での自動レポート
8. **運営エージェント（提案モードのみ）**（10 週目）
   - 毎朝の「今日やること」push
9. **仕上げ・PoC 投入**（11 〜 12 週目）
   - セキュリティ監査、患者同意フロー、運用 Runbook

**Exit 条件**:
- PoC 2 院で 2 週間連続稼働、大きなブロッカーなし
- 院長の問診 → カルテ時間が **従来比 50% 削減** を計測

## Phase 2 — β（P1 機能 + 自動化強化）

- [ ] AI エージェント **全自動モード**（PRO プラン）
- [ ] 予約キャンセル/リマインド自動化
- [ ] 施術前後写真の取り込み + 比較ビュー
- [ ] 口コミ到達率ダッシュボード、ネガ口コミアラート
- [ ] 広告文自動生成（Instagram / Google）
- [ ] 売上低下時の原因分析レポート
- [ ] 多施術者対応（最大 3 名）
- [ ] iPad ネイティブ風 PWA チューニング
- [ ] 監査ログ UI、データエクスポート

**Exit 条件**: 有料 β 10 院以上、解約率 5% 以下 / 月。

---

## Phase 3 — GA（商用ローンチ）

- [ ] 申込〜オンボーディング自動化（データインポート）
- [ ] ステータスページ、SLA 文書、サポート窓口
- [ ] 柔整レセプト連携（パートナー API 検討）
- [ ] マーケサイト、導入事例、パートナー代理店制度
- [ ] 価格 AB テスト

**Exit 条件**: 100 院導入、MRR ¥3M 以上。

---

## 主要リスクと対策

| リスク | 対策 |
|---|---|
| AI 問診品質のばらつき | Phase 1 早期から**評価セット**を整備し、Sonnet/Opus の回帰を CI で検知 |
| LLM コスト肥大化 | プロンプトキャッシュ + 院ごとの月次上限 + モデル切替 |
| 個人情報事故 | 初回から RLS・列暗号化・監査ログ、外部セキュリティ監査を GA 前に実施 |
| 導入時の既存データ移行 | Phase 0 で実データ 1 件分の移行スクリプトを検証 |
| 競合との差別化 | **AI 問診 × 部位選択 × 一気通貫エージェント**で勝負、単機能では勝負しない |
